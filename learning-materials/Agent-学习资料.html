概念学习资料 · AI 技术

Agent（智能体）

一句话定义：能围绕目标自主规划、调用工具并根据反馈循环迭代，直到完成任务的 AI 程序。

1学习目标（Learning Objectives）

学完本资料后，你应该能够：

  1. 说明 Agent 与普通 LLM 对话（Chatbot）的本质区别；
  2. 拆解 Agent 的四个核心组成部分：大模型（大脑）、规划、记忆、工具；
  3. 解释 "感知—思考—行动"循环（含 ReAct 模式）如何赋予 Agent 自主性；
  4. 分析 一个具体任务是否值得用 Agent 来做（成本、可靠性、可控性权衡）；
  5. 评价 一个 Agent 设计的优劣，指出常见的失效模式。

2核心问题（Essential Questions）

  1. ChatGPT 已经能"什么都知道"，为什么还需要 Agent？它到底多做了什么？
  2. Agent 的"自主性"从哪里来——是模型变聪明了，还是程序结构变了？
  3. 如果 LLM 每一步都可能出错，Agent 凭什么能完成复杂任务？
  4. 什么情况下不该用 Agent？

3结构化解释（Structured Explanation）

一句话定义

Agent 是以大模型为"大脑"，能自主规划步骤、调用外部工具、根据环境反馈循环调整，最终完成给定目标的 AI 程序。

拆解要点：四个组成部分

组成部分作用通俗理解
大模型（LLM）理解目标、推理决策、生成每一步的行动指令大脑：会思考、会下判断
规划（Planning）把大目标拆成子任务，决定先做什么后做什么做事的章法：先列清单再动手
记忆（Memory）短期：对话/操作历史；长期：外部存储的笔记、向量库工作台 + 笔记本
工具（Tools）搜索、读写文件、执行代码、调用 API 等与真实世界交互的能力手和脚：光想不做没结果

运作机制：感知—思考—行动循环

接收目标/观察环境→ LLM 思考（Thought）→ 决定行动（Action）→ 执行工具，获得结果（Observation）→ 回到思考……

↺ 循环进行，直到 LLM 判断"目标已完成"或触发终止条件。这个"边想边做边看结果"的模式即 ReAct（Reason + Act，Yao 等人 2022 年提出）。

这正是核心问题 2 和 3 的答案：自主性来自循环结构而非模型本身——即使每一步决策只有 90% 正确率，Agent 可以通过观察结果发现错误、自我修正（比如命令报错后换个思路重试）；而单轮对话没有"观察—修正"的机会，错了就是错了。

来龙去脉

"Agent"概念源于经典人工智能（指能在环境中自主行动以达成目标的系统，如游戏 AI、机器人）；2022 年 ReAct 论文证明 LLM 可以担任决策核心，2023 年 AutoGPT 等开源项目引爆"自主 Agent"热潮，此后演进出编程 Agent、客服 Agent、办公 Agent 等落地形态。它要解决的根本矛盾是：LLM 很聪明但只能"动嘴"，真实工作需要"动手"。

必要前置知识

  • 大语言模型（LLM）：基于海量文本训练、按概率生成文字的模型，是 Agent 的大脑。
  • Prompt（提示词）：写给 LLM 的指令文本，Agent 的每一步"思考"本质上都是一次 Prompt 调用。
  • API / 函数调用（Function Calling）：让程序之间互相调用能力的方式，是 Agent"使用工具"的技术基础。

💡 我的理解

我觉得 Agent 就像一个能自己规划步骤的智能助手。它不是简单地回答问题，而是能把一个复杂任务拆解成多个小步骤，一步步去执行。比如我想让它帮我整理一份报告，它会自己决定先去查资料，再提取重点，最后生成总结。

4应用案例（Application Cases）

生活类比：顾问 vs 全职员工

普通 Chatbot 像电话顾问——你问一句他答一句，从不替你动手；Agent 像新入职的全职员工——你给一个目标（"把这周的报销整理好交上去"），他自己拆任务、找票据、填表格，遇到缺材料会来问你，办完给你汇报结果。

真实案例：编程 Agent 修 Bug

开发者给编程 Agent 一个目标："修复登录页在手机上按钮错位的 Bug"。Agent 的实际执行过程：① 读取项目代码，定位登录页组件（工具：读文件）；② 分析样式代码，发现固定宽度写死（LLM 思考）；③ 修改 CSS 并运行测试（工具：改文件、执行命令）；④ 测试失败，观察到新的报错信息，调整方案再试（循环）；⑤ 测试通过，输出改动摘要。整个过程开发者只说了一句话。

反例/边界案例：不该用 Agent 的场景

"帮我翻译这句话"——任务单步可完成、结果可一次性验证，直接一次 LLM 调用即可。硬套 Agent 会带来三重代价：更慢（多轮循环）、更贵（多次调用）、更不可控（自主规划可能在错误方向上走很远）。工程界的共识是：能一步做完的不要用 Agent，能写死流程的用工作流（Workflow），只有路径不确定、需要随机应变的任务才交给 Agent。

5概念辨析（Concept Discrimination）

易混淆概念对照表

概念侧重点典型场景一句话区别
Agent（智能体）自主决策 + 循环 + 工具目标不确定的多步骤任务路径由 AI 自己决定，边做边调整
Chatbot（对话助手）一问一答问答、写作、翻译只输出文字，不执行动作、不闭环
Workflow（工作流）人预先编排的固定流程审批流、ETL 管道步骤写死在人手里，AI 只填充某几步
LLM（大模型）文本生成引擎被上述一切系统调用是"大脑"零件，Agent 是装了大脑的"整个人"

常见误解

误解 ① "Agent 就是写得更好的 Prompt"

❌ Prompt 只是 Agent 系统的一小部分。Agent 的本质是程序结构：循环、工具接口、状态管理、错误恢复。同样的模型，套上不同的 Agent 框架，任务完成率差异巨大。

误解 ② "Agent 比普通对话更聪明、更准确"

❌ 底层模型相同，单步准确率不变。Agent 的高完成率来自试错与自我修正的机会，但同时每一步都可能引入新错误，整体可靠性需要精心设计（限制步数、关键操作要求确认等）。

误解 ③ "Agent 一定能记住所有事"

❌ Agent 的"记忆"分短期（上下文窗口，容量有限）和长期（外部存储，需要主动写入）。没有配置长期记忆的 Agent，换一个会话就"失忆"。

    A. 规划　B. 工具　C. 更大的字体　D. 记忆

应用题

  1. 你的团队想用 AI 处理"每天把客服邮件分类：退款类转售后、咨询类自动回复、投诉类升级人工"。请分析：这个任务应该用工作流还是 Agent？判断依据是什么？如果邮件里出现完全没见过的新类型会怎样？

  1. 错。能回答问题只说明它是 Chatbot。判断关键是有没有自主行动与循环——它既不调用工具，也不根据执行结果调整行为。错的人通常把"聪明"当成了"自主"。
  2. B。模型、Prompt、记忆都只是零件；没有"观察结果→修正下一步"的循环，就没有自主性。错选 A 的人混淆了"智力"和"能动性"。
  3. C。调研任务的路径无法预先写死（搜什么、读几篇、怎么归纳都取决于中间结果），正是 Agent 的用武之地。A、D 一步可完成；B 流程固定，用工作流更稳更省。错选 B 的人低估了固定流程的确定性优势。

  5. A、B、D。规划、工具、记忆加上大脑（LLM）构成四大件；"更大的字体"与 Agent 无关。
  6. 参考分析：邮件分类 + 固定路由本身规则明确，用工作流（固定判断 → 分发）更快、更可控、成本更低；但"自动回复咨询类邮件"如果需要理解上下文、查订单、组织语气，可以在工作流的这一环嵌入 LLM 调用。若出现全新类型：工作流会把它漏掉或误分类（需要预设"兜底转人工"规则）；若整段设计成 Agent，它可能自己识别出"这像是新类型"并主动上报——这是 Agent 的优势，但代价是不确定的行为路径和更高的单件成本。结论：主干用工作流保稳定，局部用 Agent（或 LLM 调用）应对开放性——这也是目前业界的主流架构。
